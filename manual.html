1. はじめに

1.1 この仕組みの考え方

このウェブサイトは、文章ファイル（Markdownファイル）を書いて保存するだけで更新される仕組みです。ログインして使う「管理画面」はありません。更新は次の3ステップだけです。

  1. ブラウザで GitHub を開き、記事を文章ファイルとして書く
  2. 「Commit changes（コミット）」ボタンで保存する
  3. あとは自動処理が動き、1〜2分でサイトに反映される（トップページや記事一覧も自動で更新されます）

書いた記事はただの文章ファイルとして残り続けるので、サービスが変わってもデータは失われず、特別なソフトがなくても開けます。

1.2 用語のミニ辞典

用語 意味（言い換え）
GitHub（ギットハブ） ファイルを保管・公開してくれるウェブサービス。ブラウザで開いて使います
リポジトリ このサイトのファイル一式が入っている「保管庫（フォルダ）」
Markdown（マークダウン） # や - などの簡単な記号で見出しや箇条書きを表す、文章の書き方
コミット（Commit） 保存して、変更の記録を残すこと。コミットすると公開処理が自動で始まります
Frontmatter（フロントマター） 記事ファイルの先頭に書く「記事の情報カード」。タイトルや日付を書きます

2.3 サイトの保管庫（リポジトリ）を開く

  1. リポジトリ（ファイルの保管場所）のURL：https://github.com/ksu-mrtc/ksu-mrtc を開きます。
  2. このページをブックマーク（お気に入り登録）してください。 毎回ここから作業を始めます。
  3. 公開されているサイト本体のURL：https://ksu-mrtc.github.io/ksu-mrtc/ もあわせてブックマークしておくと、更新結果の確認（→ 3.7節）がすぐにできます。

3. 基本操作

まず1回、やってみる（所要 5分ほど）

いきなり新しい記事を書く必要はありません。すでにある記事の文字を1つ直して公開するのが、いちばん短い一巡です。ここを一度通せば、あとの作業はその繰り返しになります。

  1. リポジトリのトップから md → news と開き、記事ファイルを1つクリックする（→ 3.1節）
  2. 右上の ✏️ を押して、本文の文字をどこか1つ直す（→ 3.2節）
  3. Commit changes... を押して保存する（→ 3.6節）
  4. 1〜2分待って、お知らせの一覧を開いて直っているか見る（→ 3.7節）

うまくいかなくても、書き換える前の状態にいつでも戻せます（→ 4.3節）。

実際の運用でも、新しい記事を書くより、すでにある記事を直す作業のほうが多くなります。 まずこの一巡に慣れてください。

3.1 記事ファイルの置き場所と探し方

記事はすべて md/ フォルダの中に、種類ごとのフォルダで整理されています。

md/
├── index.md            … トップページ
├── news/               … お知らせ　※記事を足すのは、ふだんここです
│   ├── index.md        … お知らせの一覧ページ（記事は自動で並びます）
│   └── 2026-02-18.md   … 記事1本が1ファイル
├── center/             … 「センターについて」のページ
│   └── member/         … 製作メンバーの紹介（1人1ファイル）
├── kakiemon/           … 「柿右衛門」のページ
├── local-industry/     … 「地域産業」のページ
├── research/           … 研究成果の一覧と記事
└── parts/              … ヘッダー・フッター部品（header.md は編集禁止）
  • 図の右側の説明は、サイト上部のメニューの名前と対応しています。直したいページがどのフォルダか分からないときは、サイト側でそのページを開き、メニューのどの項目にあたるかを見てください。
  • 各フォルダの中の index.md は、そのコーナーのページ本体です。md/ 直下の index.md はトップページです。
  • お知らせ記事を探すときは、md → news の順にクリックして、ファイル名（日付入り）から目的の記事を開きます。
  • ファイルをクリックすると中身が表示されます。この時点ではまだ「見ているだけ」で、何も変わりません。

3.2 既存の記事を修正する

  1. 3.1 の手順で、修正したい記事ファイルを開きます。
  2. 画面右上の ✏️（鉛筆アイコン） をクリックすると、編集画面に切り替わります。
  3. 本文を修正します。書き方の記号は 3.4節の早見表を参照してください。
  4. 右上の Commit changes... ボタンを押します。
  5. 小さな窓が開くので、1行目（Commit message）に何をしたか一言を書きます（例：お知らせの日付を修正）。空欄のままでも保存できますが、あとで履歴を見返すときのために書くことをおすすめします。
  6. 「Commit directly to the main branch」が選ばれていることを確認し、緑の Commit changes ボタンを押します。
  7. これで保存完了です。1〜2分後にサイトへ反映されます（確認方法 → 3.7節）。

3.3 新しい記事を作る

どのフォルダに置くか、category に何を書くか

記事を置くフォルダと、情報カードの category に書く言葉は対応しています。

記事の種類 置くフォルダ category に書く言葉 並ぶ一覧ページ
お知らせ md/news/ news 「お知らせ」
研究成果 md/research/ research 「研究成果」
製作メンバー md/center/member/ member 「製作メンバー」

一覧ページ（各フォルダの index.md）に書かれた collection: と、記事の category: が同じ言葉のときに、その記事が一覧に並びます。category の行を消すと一覧から外れるのは、このためです（→ 3.8節①）。

kakiemon・local-industry と、center の直下は、記事を並べる一覧を持たない1枚もののページです。ここを直すときは新しく記事を作らず、3.2節の手順でそのフォルダの index.md を編集します。

手順

  1. md → news フォルダ（記事を置きたいフォルダ）を開きます。
  2. 右上の Add file → Create new file をクリックします。
  3. 一番上の欄にファイル名を入力します（ルールは下記）。
  4. 本文欄に、下のテンプレートを貼り付け、（　） の部分をすべて書き換えます（かっこごと消します）。
  5. Commit changes... → メッセージを書く → 緑の Commit changes（3.2 の手順4〜6と同じ）。

貼り付けるテンプレート（再掲）

---
title: "（記事のタイトル）"
date: "（2026-07-15 の形で日付を書く）"
category: "news"
description: "（一覧に表示される1〜2文の説明）"
image: "images/news/（画像ファイル名）"
---

## （見出し）

（本文をここに書きます。段落を分けるときは空の行を1行はさみます）

- （箇条書きの項目）
- （箇条書きの項目）

（　） が入っている行は、かっこごと消して書き換えてください。 画像を使わない記事では image: の行ごと削除します。

ここに載せたものと同じテンプレートが 付録A にもあります。印刷して使うときは、そちらを切り離して手元に置くと、行き来せずに済みます。

ファイル名のルール

  • 半角の英数字とハイフン（-）だけを使う。日本語・スペース・全角文字は使わない
  • 日付-内容.md の形にする　例：2026-07-15-summer-event.md
  • 最後は必ず .md で終わる
  • index.md という名前は一覧ページ専用なので、記事には使わない

記事の並び順は情報カードの date で決まるため、ファイル名そのものは表示に影響しません。それでも日付から始めてください。 あとからファイルを探すとき、名前だけで見分けられるようにするためです。

記事の情報カード（Frontmatter）の書き方

記事ファイルの先頭には、--- で挟んだ「情報カード」を書きます。

---
title: "夏の企画展のお知らせ"
date: "2026-07-15"
category: "news"
description: "8月1日から夏の企画展を開催します。"
image: "images/news/2026-07-15-summer.jpg"
---

値は "（半角の二重引用符）で囲むのがこのサイトの決まりです。既存の記事ファイルを開くと同じ書き方になっているので、迷ったらそちらを見本にしてください。

項目 意味 書き方の注意
title 記事のタイトル 日本語でOK
date 日付 必ず 2026-07-15 の形式（年4桁-月2桁-日2桁）。この日付で一覧の並び順が決まります
category 記事の種類 お知らせ記事は news と書きます（一覧に載せるための目印です）
description 一覧に表示される短い説明 1〜2文まで。長文は本文へ
image 一覧に表示される画像 画像の場所を書く（画像の追加方法 → 3.5節）。画像なしならこの行ごと削除

よくある書き間違い（表示が崩れる原因のほとんどはこれです）

  • 「:（コロン）」のあとに半角スペースを1つ入れる（title:夏の… は×、title: 夏の… が○）
  • コロンを全角（：）で書かない。必ず半角の :
  • 値は半角の " で囲む（title: 夏の… ではなく title: "夏の…"）。" を閉じ忘れない
  • 1行目と最後の --- を消さない（--- は半角ハイフン3つ）
  • 日付を 2026/7/15 や 7月15日 と書かない
  • 各項目は1行におさめる（途中で改行しない）

3.4 Markdown記法の早見表（本文の書き方）

--- の下は、ふつうの文章として本文を書きます。よく使う記号は次の5つだけ覚えれば十分です。

したいこと 書き方 表示
見出し ## 開催概要 大きめの見出しになる
小見出し ### 日時 少し小さい見出し
箇条書き - 項目名（半角ハイフン＋半角スペース） ・項目名
太字 **重要** 重要
リンク [センターの紹介](?p=md/center/index.md) クリックできる文字
  • 段落を分けるときは、空の行を1行はさみます。
  • 記号（# - *）はすべて半角で、記号のあとに半角スペースが必要です。
  • 書いた文章を一時的に伏せたいときは、その範囲を <!-- と --> で挟みます。挟んだ部分は画面に出なくなりますが、文章はファイルの中に残ります（→ 3.8節②）。

3.5 画像を載せる

写真を記事に入れる作業は、2つに分かれています。

  1. 画像ファイルを images フォルダへアップロードする（→ 1回目のコミット）
  2. 記事の中に、その画像の場所を書く（→ 2回目のコミット）

保存は2回必要です。 順番もこのとおりで、先に画像を入れてから記事に書きます。

準備：アップロードする前に

形式　.jpg または .png にしてください。iPhone の標準形式（HEIC）は、そのままではブラウザで表示できません。 iPhone の写真を使うときは「設定 → カメラ → フォーマット →『互換性優先』」に変えて撮り直すか、いったんメールやLINEで送って変換されたものを使います。

大きさ　1枚あたり1MB以内、長辺1600px程度を目安に小さくしてから上げてください。カメラやスマートフォンの写真は1枚5〜25MBあり、そのまま上げるとページがなかなか開きません。

縮小のしかた
Windows 画像を右クリック →「プログラムから開く」→「フォト」→「…」→「画像のサイズ変更」
Mac 画像をダブルクリックして「プレビュー」で開く → メニューの「ツール」→「サイズを調整」

ファイル名　半角の英数字とハイフンだけにします（例：2026-07-15-summer.jpg）。日本語やスペースが入っているときは、アップロードする前にパソコン側で名前を変えてください。

① 画像をアップロードする（1回目のコミット）

  1. リポジトリのトップから images フォルダを開き、入れたいフォルダまで進みます（お知らせの写真なら images → news）。

    ここが一番間違えやすいところです。 Upload files は「いま開いているフォルダ」に画像を置きます。リポジトリのトップで押すとトップに置かれてしまい、記事から呼び出せません。いまどこにいるかは画面上部のパス表示で確かめられます（→ 2.4節）。

    入れたいフォルダが無いときは、担当者に相談してください（現在あるのは news・kakiemon・slideshow などです）。

  2. Add file → Upload files をクリックします。

  3. 画像を選びます。やりやすいほうで構いません。

    • 枠の中へ画像をドラッグ＆ドロップする
    • 枠の中の choose your files をクリックして、ファイルを選ぶ

  4. 画面の下の緑の Commit changes を押します。これが1回目の保存です。

  5. フォルダの一覧に画像ファイルが並んでいることを確かめます。

② 記事に画像の場所を書く（2回目のコミット）

書き方は2つあり、役割が違います。同じものを2度書くわけではありません。

書き方 何に使うか
情報カードの image: 一覧に並んだときの小さな写真（サムネイル）。記事の本文には出ません。1記事に1枚だけ
本文中の ![ ]( ) 記事本文の中に出る写真。何枚でも置けます 
---
（略）
image: "images/news/2026-07-15-summer.jpg"
---

## 当日の様子

![会場に並んだ柿右衛門様式の皿](images/news/2026-07-15-summer.jpg)
  • 場所は images/ から、先頭から書きます。
  • 書けたら Commit changes で保存します。これが2回目の保存です。
  • 表示の確認は3.7節の手順で行います。

写真の説明（![ ] の中に書く文字）

角かっこの中に書く文字は、写真が表示できないときに、代わりに出る文字です。あわせて、将来その画像ファイルが開けなくなったときに、それが何を写したものだったかを残す役割があります。

  • ×　![写真の説明](images/news/2026-07-15-summer.jpg)
  • ○　![会場に並んだ柿右衛門様式の皿](images/news/2026-07-15-summer.jpg)

「写真の説明」のままにせず、写っているものを短く書いてください。

画像を差し替える・消す

  • 差し替える：新しい画像を①の手順でアップロードし、記事の中の場所を新しいファイル名に書き換えます。同じファイル名で上書きすると、ブラウザが古い画像を覚えていて、しばらく変わらないことがあります（強めの再読み込み → 2.1節）。
  • 記事から外す：記事の中の ![ ]( ) の行、または image: の行を消します。画像ファイルそのものは images に残ります。
  • 画像ファイルごと消す：images の中の画像を開き、「…」メニューの Delete file → Commit changes。その画像を使っている記事があると、そこが表示されなくなります。 先に記事側を直してください。

3.6 保存して公開する（Commit）

保存する前に、プレビューで見え方を確かめる

編集画面の上のほうに Preview というタブがあります（隣は Edit）。

  1. 本文を書き終えたら Preview タブをクリックします。
  2. 見出し・箇条書き・リンク・画像が、思ったとおりに出ているか確かめます。
  3. 直したいところがあれば Edit タブに戻って書き直します。

この仕組みは、書き間違いを自動では教えてくれません。 公開してしまう前に自分の目で確かめられるのは、ここです。 なお、情報カード（--- で挟んだ部分）はプレビューでは表のように表示されます。本文の見え方を確かめるための機能だと考えてください。

Commit で保存する

どの操作でも、最後は必ず Commit changes です。これが「保存ボタン」であり「公開ボタン」です。

  1. Commit changes... を押す
  2. 1行目に、何をしたか一言メモ（例：夏の企画展の記事を追加）
  3. 「Commit directly to the main branch」が選ばれたまま、緑の Commit changes を押す

コミットのたびに「いつ・誰が・何を変えたか」が自動で記録されます。この記録はあとからいつでも見られます（→ 5.1節）。

3.7 公開されたか確認する

  1. コミット後、1〜2分待ちます。
  2. サイト本体を開き、書いた記事が並ぶ一覧ページ（お知らせ記事なら上部メニューの「お知らせ」）を開きます。
  3. ブラウザの再読み込み（Windows は 〔Ctrl〕＋〔R〕 または 〔F5〕／Mac は 〔⌘〕＋〔R〕）をします。
  4. 一覧に記事が出ていれば成功です。記事名をクリックして、本文と画像も表示されるか確かめてください。
  5. すぐに反映されていないときは、リポジトリ画面上部の Actions タブを開きます。
    • 実行中（黄色の●）→ もう少し待つ
    • 緑のチェック ✓ → 処理成功。ブラウザをもう一度再読み込み
    • 赤い × → 処理が失敗（→ 4.1節）

確認はトップページではなく、一覧ページで行ってください。 トップページの「最新ニュース」に出るのは、お知らせのうち日付がいちばん新しい1件だけです。しかも新しさを決めているのは保存した時刻ではなく、情報カードの date です。過去の日付を書いた記事は、正しく公開されていてもトップページには出ません。

3.8 記事を一旦見えなくする／取り下げる

「見えなくしたい」には段階があります。どこまで見えなくしたいかで手順が変わるので、まず次の表で選んでください。

したいこと 操作 元に戻すには
① しばらく一覧から外したい（文章は残す） category: の行を消す 行を書き戻す
② 書きかけの部分だけ伏せたい その範囲を <!-- と --> で挟む 記号を外す
③ 記事ごと取り下げたい Delete file で削除する 4.3節の手順で戻す

①と②は「一覧に出さない」であって、「公開を取り消す」ではありません。 記事のURLを知っている人は、そのページを開けば読めます。人目に触れないようにしたいときは③を選んでください。

① 一覧から外す（ファイルは残す）

  1. 3.2節の手順で記事ファイルを開き、編集画面（鉛筆アイコン）にします。
  2. 情報カードの中の category: "news" の行を、行ごと消します。
  3. Commit changes で保存します（→ 3.6節）。

1〜2分でお知らせ一覧とトップページの「最新ニュース」から消えます。戻したくなったら、同じ場所に category: "news" の行を書き戻してコミットすれば、また一覧に出ます。

消すのは category: の1行だけです。--- の行や title: を消すと、ページの表示が崩れます（→ 4.2節）。

② 本文の一部だけ隠す

隠したい範囲を <!-- と --> で挟みます。

<!--
この部分は画面に表示されません。
書きかけの段落を、しばらく伏せておきたいときに使います。
-->

挟んだ部分は表示されませんが、文章はファイルの中に残っています。 <!-- と --> の2行を消せば、また表示されます。

③ 完全に取り下げる（削除）

  1. 削除したい記事ファイルを開きます。
  2. 右上の 「…」メニュー（または鉛筆アイコンの隣）から Delete file を選びます。
  3. Commit changes で確定します。一覧からも自動で消えます。

消しても記録は残るので、あとから元に戻せます。 手順は 4.3節にあります。「消したら二度と戻らない」ということはありません。

ページごと（コーナーごと）メニューから外したいときは、記事ではなくサイトの構成を変える操作になります。5.3節を見てください。

4. 困ったとき

4.1 保存したのにサイトに反映されない

次の順で確認してください。

  1. 2分待ちましたか？ 反映には時間がかかります。
  2. 再読み込みしましたか？ ブラウザが古い表示を覚えていることがあります。Windows は 〔Ctrl〕＋〔R〕（それでもだめなら 〔Ctrl〕＋〔Shift〕＋〔R〕）、Mac は 〔⌘〕＋〔R〕（それでもだめなら 〔⌘〕＋〔Shift〕＋〔R〕）。
  3. Actions タブは緑✓ですか？ 赤×のときは処理が失敗しています。多くの場合、直前に保存したファイルの情報カード（Frontmatter）の書き間違いが原因です。4.2 のチェック項目を確認して修正・再コミットしてください。それでも赤×が続く場合は 4.4節へ。

4.2 記事が一覧に出ない・表示がおかしい

原因のほとんどは情報カードの書き間違いです。該当ファイルを開き、次を確認してください。

  • [ ] 1行目が ---（半角ハイフン3つ）で始まっているか。情報カードの終わりにも --- があるか
  • [ ] コロンは半角の : か。コロンの後に半角スペースがあるか
  • [ ] 値は半角の " で囲まれ、閉じ忘れがないか
  • [ ] date は 2026-07-15 の形式か
  • [ ] お知らせ記事なら category: "news" と書いてあるか（News や ニュース は×）
  • [ ] image に書いた場所と、実際に画像を置いた場所が一致しているか（画像なしなら image の行ごと削除したか）
  • [ ] ファイル名が半角英数字で、.md で終わっているか

4.3 間違えて保存してしまった（元に戻したい）

コミットの記録が残っているので、前の状態はいつでも見られます。

  1. 該当ファイルを開き、右上の History をクリックします。
  2. 変更の一覧が新しい順に並びます。戻したい時点（間違える前）の記録をクリックします。
  3. その時点のファイルの中身が表示されるので、本文を全部選択してコピーします。
  4. 通常の手順（3.2節）でファイルを開いて編集し、中身をコピーした内容に貼り替えてコミットします。

うまくいかないとき・ファイルを丸ごと消してしまったときは、無理をせず相談してください（→ 4.4節）。記録が残っているので、必ず復元できます。

4.4 どうしても解決しないとき（何を伝えればよいか）

自分だけで解決しようとせず、サイトの管理担当者に相談してください。そのとき、次の3つを伝えると原因をたどりやすくなります。

  • どのファイルを（例：md/news/2026-07-15-summer.md）
  • 何をしようとして（例：新しいお知らせを追加しようとした）
  • どうなったか（エラー表示など、可能なら画面の写真）

何をしても、コミットの記録は残っています。 取り返しのつかない状態にはならないので、慌てずに現状のまま相談してください。自己流で直そうとするより、そのほうが早く戻せます。

5. 少し進んだ操作（読まなくても運用できます）

5.1 変更の記録を見る

  • ファイルごとの記録：ファイルを開いて History。「いつ・誰が・どんなメモで」変更したかの一覧が見られます。
  • サイト全体の記録：リポジトリのトップで、ファイル一覧の上にある最新コミットの表示から 「○○ commits」 をクリック。

すべての変更が自動で記録されているため、「誰かが触って壊れたまま分からなくなる」ことがありません。これがこの仕組みの安心材料のひとつです。

5.2 トップページのスライドショー画像を入れ替える

トップページで切り替わる大きな写真は、images/slideshow/ フォルダの中身ではなく、リポジトリのトップにある slideshow.json というファイルが決めています。 画像を上げただけでは表示されません。画像のアップロードと、slideshow.json の書き換えの両方が必要です。

  1. 3.5節①の手順で、images → slideshow フォルダに画像をアップロードします。

    • スライドショーは画面いっぱいに表示されるため、長辺2000px程度・1MB以内を目安にしてください。

  2. リポジトリのトップに戻り、slideshow.json を開いて編集します。中身は次の形です。

    [
  {
    "src": "images/slideshow/hakata-ningyo-01.jpg",
    "alt": "黒い台座に並べられた博多人形。手前は十二単をまとった女性の人形"
  },
  {
    "src": "images/slideshow/tateito-03.jpg",
    "alt": "手織機に張られた橙色の経糸と、織り上がりつつある緑と白の縞の織物"
  }
]
    • src … 画像の場所。images/slideshow/ から先頭から書きます。
    • alt … その写真に何が写っているかの説明（→ 3.5節「写真の説明」）。
    • 表示される順番は、ファイル名の順ではなく、この中に書いた順です。
    • 1枚分は { } で挟んだ2行で、枚数分を ,（半角カンマ）で区切って並べます。最後の1枚のうしろにはカンマを付けません。

  3. Commit changes で保存します。

画像を減らすときは、slideshow.json の側を先に直してください。 画像ファイルだけ Delete file で消すと、slideshow.json には場所が残ったままになり、トップページに壊れた写真の枠が出ます。

5.3 新しいコーナー（メニュー項目）を増やしたいとき ※管理者向け

md/ の直下に新しいフォルダを作り、その中に index.md を置いて、情報カードに navTitle:（メニューに表示する名前）と navOrder:（並び順の数字）を書くと、サイト上部のメニューに自動で追加されます。記事一覧を自動表示させたい場合は collection: に記事の category と同じ言葉を書きます。通常の記事更新では使わないため、詳細は管理者にご相談ください。

5.4 バックアップ（クローン）について ※管理者向け

このサイトの全データ（記事・画像・仕組みのすべて）は、リポジトリを「クローン（複製）」することで、手元のパソコンに丸ごとコピーできます。リポジトリのトップの緑の Code ボタン → Download ZIP でも一式を取得できます。定期的（例：月1回）に取得して保管しておくと、万一サービスに障害があってもサイト全体を復元できます。

付録A　新規記事テンプレート（コピーして使う）

書き方の説明は 3.3節にあります。ここは、貼り付けて使うためのテンプレートです。

---
title: "（記事のタイトル）"
date: "（2026-07-15 の形で日付を書く）"
category: "news"
description: "（一覧に表示される1〜2文の説明）"
image: "images/news/（画像ファイル名）"
---

## （見出し）

（本文をここに書きます。段落を分けるときは空の行を1行はさみます）

- （箇条書きの項目）
- （箇条書きの項目）

（　） が入っている行は、かっこごと消して書き換えてください。 書き換えずに残すと、そのまま画面に出ます。画像を使わない記事では image: の行ごと削除します。
